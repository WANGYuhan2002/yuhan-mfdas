# IN_DAS_data —— DAS 连续原始数据样本

> **GitHub 版说明：** 原始 DAS 数据一律不进 GitHub 仓库，所以这里本目录只有本说明和 `README.md`。下文描述的样本在 Zenodo 存档 [10.5281/zenodo.20715241](https://doi.org/10.5281/zenodo.20715241)（`matched_filter_release.zip` → `yuhan_dasmf_v1.0/IN_DAS_data/continuous_scan_1h/`）里；要跑 Run_1 演示，请把它拷进本目录。下文所说「附带」都指该存档。

本文件夹存放跑通流程所需的**连续 DAS 原始数据样本**（80 Hz、道间距 dx≈16.34 m、936 通道、应变率）。
完整数据集（2024-04-23 → 06-22，约 59 天，~1.4 TB）不随发布版附带；这里只放一小段可演示的样本。

## 目录结构

```
IN_DAS_data/
└── continuous_scan_1h/          连续 1 小时样本（供 Run_1 模板匹配扫描演示）
    └── 20240425/                2024-04-25 15:00–16:00（当天地震最活跃的一小时，205 个 MF 事件）
        └── Gr_80Hz_16m_20240425_HHMMSS.861.h5   × 13 个（每个 5 分钟 ~84 MB，共 ~1.1 GB）
```

> 文件按加载器约定布局为 `<input_dir>/YYYYMMDD/*.h5`；文件名结尾 `..._YYYYMMDD_HHMMSS.fff.h5`
> 被加载器当作该文件的起始时刻解析（5 分钟一个文件）。这里的 13 个文件覆盖 14:59:55–16:04:55，
> 完整包含 15:00:00–16:00:00。

## 为什么是这一小时

- **04-25**：与发布版已附带的中间产物对齐——`Output_1/SCCs_h5/` 恰好只附带 2024-04-25 一整天的叠加互相关序列，
  所以用这一天的原始 DAS 能让你「从大数据重算 SCCs」并与现有 `SCCs_h5/*/...20240425...h5` 逐文件对照校验。
- **15:00–16:00**：这一小时是 04-25 检测到地震最频繁的时段（205 个 MF 事件），适合做检测演示。

## 怎么用（数据流一眼可见，无 config / 无环境变量）

- **Run_1**（`1_Compute_SCCs_10min_h5_Parallel_io_once.py`）做模板匹配扫描。它通过 `functions/readers.py`
  的 `Read_DAS_data` 读原始 DAS，该函数默认读本目录 `IN_DAS_data/continuous_scan_1h/`（Zenodo v1.0.0 版代码里
  指向作者的归档挂载点 `.../DATA_DEC_80Hz_16m_SORTED/`）。把扫描时间窗（脚本 `Config` 里的
  `t_all_start`/`t_all_end`）限到 2024-04-25 15:00–16:00 即可。
- 其余检测步骤（Run_2 触发、Run_3 振幅、Run_4 分类/估震级、Run_6 对比）**不需要**连续 DAS，
  直接吃发布版已附带的中间产物（`Output_1/2/3/4`）即可。（GitHub 版更正：重跑 Run_3 本身会经 `Read_DAS_data`
  在每个触发时刻读原始 DAS；Run_4 及之后可以直接从附带的 `Output_3/` 开始。）

## 未附带的部分

- **模板事件原始文件**（5 个模板各对应一个 ~84 MB 原始 h5，跨 2024-04-25/05-10/05-11/05-30 共 ~423 MB）
  **暂未附带**——前期「选模板」(Run_0) 还会用到更大范围的 DAS，体量待作者进一步斟酌后再定。
  在此之前，发布版已自带定稿模板（`Output_0_Template_library/Template_npy_files/*.npy`），
  可直接从 Run_1 起跑，无需自行造模板。
- 8 Hz / 400 Hz_raw 等其它数据产品本流程用不到，不附带。
