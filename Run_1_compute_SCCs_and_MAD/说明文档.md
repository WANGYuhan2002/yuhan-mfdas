# Run_1_compute_SCCs_and_MAD 说明文档

## 本 release 脚本分类

### 【主线】

- `1_Compute_SCCs_10min_h5_Parallel_io_once.py`：SCCs 计算主线版本。每 10 分钟窗口只读一次 DAS 连续数据，所有模板复用该段数据，显著减少 I/O 次数。配合 5 个 `template_*_80Hz` 模板运行。
- `2_MAD_of_SCCs_calculation_Parallel.py`：MAD 及统计量计算主线版本。并行读取 SCCs h5，按固定时窗统计 5 类统计量，写 pkl。

### 【旧版（可忽略，已保留原地）】

- `1_Compute_SCCs_10min_h5_Parallel.py`：历史 v3 版本。逐 `(模板, 窗口)` 重复读盘，路径指向 `matched_filter_v3`，使用 13 个旧模板（`temp_0..temp_12`），输出到 `SCCs_h5_6h/`，与本 release 数据不一致，不可直接运行复现现有结果。
- `2_MAD_of_SCCs_calculation.py`：历史 v3 版本。路径指向 `matched_filter_v3`，计算主体已被整体注释，运行时仅做 load+出图，属一次性探索脚本。

## 一、文件夹概述与在整体流程中的位置

本文件夹是模板匹配流程的**第 1 步**，负责两件事：

1. **计算叠加互相关 SCCs（Stacked Cross-Correlation Coefficient）**：用 Output_0 产出的模板库，沿 Kefalonia DAS 连续数据滑动做归一化互相关，再在通道维（空间）上取平均（叠加），得到随时间变化的相关系数曲线。
2. **计算 MAD（Median Absolute Deviation，中位绝对偏差）**：对 SCCs 曲线按固定时窗统计 MAD，作为后续触发检测的噪声基准（触发阈值 = MAD × level）。

**上游来源**：

- 模板 `.npy` 文件：`{PROJECT_ROOT}/Output_0_Template_library/Template_npy_files/`（由 Run_0 产生）。
- 连续 DAS 数据：80 Hz 归档 `DATA_DEC_80Hz_16m_SORTED/`（80 Hz、16 m 道间距，外部原始数据，非本项目产出），由 `functions/readers.py` 的 `Read_DAS_data` 从包内默认位置 `IN_DAS_data/continuous_scan_1h/` 读取（可把归档或 Zenodo 存档里的 1 小时样本放到或软链接到这里）。

**下游去往**：

- `{PROJECT_ROOT}/Output_1_SCCs_and_MAD/SCCs_h5/<模板名>/CCs_stack_*.h5`：被 **Run_2**（触发）、**Run_3**（峰值振幅）等后续步骤通过 `functions/readers.py` 的 `Read_CCs_stack_h5` 读取。
- `{PROJECT_ROOT}/Output_1_SCCs_and_MAD/MAD_arrays/.../MAD_Average_dict.pkl`：被 **Run_2** 读取，用作触发阈值刻度（Run_2 读 `12:00:00/MAD_Average_dict.pkl`）。

整体流程：`Run_0（模板库）→ 【Run_1：本文件夹，SCCs + MAD】→ Run_2（触发）→ Run_3（峰值振幅）→ Run_4/5/6（后续分析）`。

## 二、脚本逐个说明

### 脚本 1：`1_Compute_SCCs_10min_h5_Parallel_io_once.py` 【主线，SCCs 计算】

- **作用**：把整个观测期切成 10 分钟窗口，每个窗口**只读一次 DAS 数据**，对所有 5 个模板分别计算叠加互相关 SCCs，逐窗口逐模板存为 h5。
- **输入**：
  - 模板：`Output_0_Template_library/Template_npy_files/` 下的 5 个 `.npy`（`template_0423_80Hz` / `template_0425_80Hz` / `template_10_80Hz` / `template_8_80Hz` / `template_20_80Hz`），开跑前 `preload_all_templates` 一次性全部加载进内存。
  - 连续数据：80 Hz DAS 归档（`IN_DAS_data/continuous_scan_1h/`），由 `Read_DAS_data(t_start, t_end_for_read, ...)` 读取。
  - 关键参数（`Config` 类硬编码）：`fs=80`、`freq_band=[8,20]`、`das_dist_start=8300`、`das_dist_end=14000`、`dx≈16.335`、时间范围 `2024-04-24 10:20:00 → 2024-06-22 17:10:00`、`t_delta=10min`、`cpu_workers=min(10, 0.2×核数)`。
- **输出**：`Output_1_SCCs_and_MAD/SCCs_h5/<模板名>/CCs_stack_<模板名>_UTC_YYYYMMDD_HHMMSS.ffffff.h5`，每个 h5 含 `CCs_s`（叠加后归一化互相关系数曲线，1D，48001 点）与 `RAWCCs_s`（叠加后原始未归一化互相关，1D）。同时在 `SCCs_h5/` 下写 `config.json`。
- **核心处理逻辑**：
  1. `preload_all_templates`：加载全部模板到字典；`get_max_template_length` 取最长模板样本数。
  2. 为 `t_array` 中每个 10 分钟起点构造任务，`ProcessPoolExecutor` 并行，**并行粒度 = 时间窗口**。
  3. `process_single_time_window_for_all_templates`：每窗口只调用一次 `Read_DAS_data`（读取时长 = 10 分钟 + 最长模板时长），然后内循环所有模板复用该数据段。
  4. 对每个模板：若输出 h5 已存在则跳过（支持断点续算）；否则 `CCs_comp` 计算逐时刻逐通道的 `CCs_f`/`RAWCCs_f`，裁切到 `expected_samples`（48001 点），通道维取均值得 `CCs_s`/`RAWCCs_s`，`write_h5` 存出。
- **依赖的 functions 模块**：`readers.Read_DAS_data` / `Read_template` / `write_h5`；`compute_correlation.CCs_comp`；`pydas_readers`、`load_das_h5_PE2024`（经 readers 间接使用）。

### 脚本 2：`1_Compute_SCCs_10min_h5_Parallel.py` 【旧版 / v3，可忽略】

- **作用**：功能目标同脚本 1，但路径全部指向 `matched_filter_v3`，模板为 13 个 `temp_0..temp_12`，`freq_band=[5,20]`，输出到 `SCCs_h5_6h/`，与本 release 现有数据不一致。每个 `(模板, 窗口)` 任务各自读一次 DAS（同一窗口被重复读 N 次），无输出裁切。是脚本 1 的前身，已被取代，**在本 release 下不可直接运行复现现有结果**。

### 脚本 3：`2_MAD_of_SCCs_calculation_Parallel.py` 【主线，MAD 计算】

- **作用**：读取脚本 1 产出的 SCCs h5，按固定时窗（默认 1 小时）并行统计每个模板 SCCs 的 5 类统计量（MAD / Median / Mean / MeanAbsDev / PeakCCs），存 pkl 并出图。
- **输入**：
  - `{PROJECT_ROOT}/Output_1_SCCs_and_MAD/SCCs_h5/`（脚本 1 的输出）。
  - 5 个模板；关键参数：`NUM_CPUS=20`、`nt_delta_arr=[1*60]`（统计时窗 60 分钟）、时间范围同脚本 1。
- **输出**：`Output_1_SCCs_and_MAD/MAD_arrays/20240424_102000_to_20240622_171000/<t_delta>/` 下：
  - `MAD_array_dict.pkl`、`Median_array_dict.pkl`、`MEAN_array_dict.pkl`、`MEANAbsDev_array_dict.pkl`、`PeakCCs_array_dict.pkl`（每模板一条逐时窗序列）。
  - `MAD_Average_dict.pkl`（每模板整段平均 MAD，**下游 Run_2 消费的核心文件**）。
  - 出图 `SCCs_MAD_array_AllTemp.png`、`SCCs_Statistics_array_AllTemp_inOne.png`。
- **核心处理逻辑**：
  1. 构造时窗边界数组；外层逐模板，内层为每个时窗段构造任务，`ProcessPoolExecutor.map` 并行调用 `calculate_mad_for_chunk`（并行粒度 = 时窗段）。
  2. `calculate_mad_for_chunk`：用 `Read_CCs_stack_h5` 拼接该时窗内所有 10 分钟 SCCs 文件，用 `np.nanmedian/nanmean/nanmax` 计算 5 个统计量。
  3. 汇总写 pkl，再算整段平均 MAD 写 `MAD_Average_dict.pkl`，最后出图。
  - 输出子目录名由 `str(timedelta(minutes=nt_delta))` 决定，60 分钟 → `"1:00:00"`，720 分钟 → `"12:00:00"`。
- **依赖的 functions 模块**：`readers.Read_CCs_stack_h5` / `write_pkl` / `load_pkl`；`plot.Ticks_xaxis_day_or_hour`。

### 脚本 4：`2_MAD_of_SCCs_calculation.py` 【旧版 / v3，可忽略】

- **作用**：MAD 计算的早期非并行版本。路径指向 `matched_filter_v3`，13 个旧模板，`nt_delta=[240]`（4 小时）。**真正的串行计算主体已被整体注释**，运行时仅做 load 已有 pkl → 重算 `MAD_Average_dict.pkl` → 出图。jupytext 导出格式，含大量注释掉的会议出图代码。已被脚本 3 取代，**在本 release 下不产出现有 MAD 数据**。

                ▼

## 四、数据格式说明

### 4.1 SCCs h5 文件（脚本 1 产生，Run_2/3 等消费）

- **命名**：`SCCs_h5/<模板名>/CCs_stack_<模板名>_UTC_<YYYYMMDD>_<HHMMSS.ffffff>.h5`，文件名 UTC 时间为该 10 分钟窗口起点。
- **内容**：
  - `CCs_s`：shape `(48001,)`，`float64`。叠加（通道维平均）后的归一化互相关系数时间序列；48001 = 10 min × 60 s × 80 Hz + 1。取值范围约 ±0.x，越接近 1 越像模板。
  - `RAWCCs_s`：shape `(48001,)`，`float64`。叠加后的原始未归一化互相关，量级极小（约 1e-5）。
- **读写**：由 `functions/readers.py` 的 `write_h5` 写、`Read_CCs_stack_h5` 读（按文件名时间戳排序、拼接指定区间内多个 10 分钟文件成连续序列）。

### 4.2 MAD 等统计量 pkl（脚本 3 产生，Run_2 消费）

- **路径**：`MAD_arrays/20240424_102000_to_20240622_171000/<t_delta>/`，实测 `<t_delta>` 有 `1:00:00/` 与 `12:00:00/` 两个子目录（分别由 `nt_delta=60` 与 `720` 运行产出）。
- **文件结构**（均为 dict，key 包含 `'t_array'` 与 5 个模板名）：
  - `MAD_array_dict.pkl` / `Median_array_dict.pkl` / `MEAN_array_dict.pkl` / `MEANAbsDev_array_dict.pkl` / `PeakCCs_array_dict.pkl`：`t_array` 为时窗边界数组，每个模板 key 对应该时窗内 SCCs 的对应统计量序列（shape 与时窗段数一致）。
  - `MAD_Average_dict.pkl`：每个模板 key → 整段观测期平均 MAD（shape `(1,)`，`float64`）。**Run_2 触发时实际加载 `12:00:00/MAD_Average_dict.pkl` 用作阈值刻度**。
- **配套出图**：`SCCs_MAD_array_AllTemp.png`、`SCCs_Statistics_array_AllTemp_inOne.png`（脚本 3 产出）。

### 4.3 config.json（脚本 1 产生）

- **路径**：`SCCs_h5/config.json`。记录 `fs=80`、`freq_band=[8,20]`、`das_dist_start=8300`、`das_dist_end=14000`、`dx≈16.335`、5 个模板名、输入输出目录，与脚本 1 的 `Config` 完全一致。
