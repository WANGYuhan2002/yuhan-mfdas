## 本 release 脚本分类

- **【主线】`1_Record_Amp_Parallel.py`**：在每个触发时刻回到外部连续 DAS 数据（80 Hz 归档 `DATA_DEC_80Hz_16m_SORTED/`，默认位置 `IN_DAS_data/continuous_scan_1h/`），并行提取各通道峰值振幅。输入：`../Output_2` 触发点 + `../Output_0` 模板库 + `../Output_1` MAD；输出：`../Output_3_Trig_PeakAmp/`。
- **【旧版，可忽略，已保留原地】`1_Record_Amp.py`**：历史 v4 串行版。原本路径写死至 `matched_filter_v4`，现已加 bootstrap 块做相对化，但内部逻辑仍是 v4 旧版（带通 5–20Hz、硬编码 13 个模板名、引用未定义的 `config` 对象而无法直接运行）。**不应使用**，仅供历史溯源。

> ### ⚠️ Run_3 在「最终方案」中的定位（重要）
>
> Run_3 记录的是**逐次触发的峰值振幅**。它**不进入最终采用的震级 `Real_Mag`** —— 最终震级由 `Run_4/2b` 用 **`max_RAWCCs`（未归一化互相关）× 模板自身振幅**（`Template_library.csv` 的 `amp_max_mean/self_CC`，由 Output_0 提供的逐模板常数）标定、再用 NOA/IMS 做线性回归得到。
>
> Run_3/Output_3 的逐事件振幅只用于：(1) 一个**可选的、基于振幅的震级估计分支** `Quasi_Mag_Amp`（与主线 `Real_Mag` 并列的备选列，不替代它）；(2) 「`max_RAWCCs` vs 峰值振幅」对照/验证图（`2b_999`、`max_RAWCCs_vs_peakAmp/`、`5_Show` 的 amp–mag 拟合）。
>
> **因此 Run_3 不在最终震级的关键路径上，属可选步骤。** 本 release **有意保留它（不删除）**，以保留「用振幅估震级」这一备选方案，供日后可能使用。
>
> 注意一个现状（仅说明，未改动）：`Run_4/2b` 当前代码**仍会无条件读取** `Trig_MAX_amp_df.csv`，所以单独运行 2b 时该文件需存在；但其数值不影响 `Real_Mag`。若将来确定不再需要振幅分支，可在 2b 中解耦这处读取。

## 一、文件夹概述与在整体流程中的位置

本文件夹负责模板匹配流程的**第 3 步：在每个触发点回到 DAS 原始连续数据，提取各通道峰值振幅**。

MF 流程中为节省存储，只保存了叠加互相关 SCCs（Output_1）和触发点（Output_2），没有保存完整 DAS 波形。要做震级估计，需在触发时刻回查原始数据，取触发时间窗内各通道最大绝对振幅。

- **上游来源**：
  - `../Output_2_Triggered_SCCs_points/level_<N>/`（触发点 pkl，按 level/template 存放，经 `Read_Collapse_group_df` 读入）
  - `../Output_0_Template_library/Template_library.csv`（模板名 `infile_name` 与 P/S 走时偏移 `t_P_sec`、`t_S_sec`）
  - `../Output_1_SCCs_and_MAD/MAD_arrays/.../12:00:00/MAD_Average_dict.pkl`（MAD 基准，用于把 `CCs_s_trig` 归一化成 `CCs_s_trig_ofMAD`）
  - **DAS 原始连续数据**：80 Hz 归档 `DATA_DEC_80Hz_16m_SORTED/`，默认位置 `IN_DAS_data/continuous_scan_1h/`（80Hz、16m 道间距，由 `Read_DAS_data` 读取）
- **本步输出**：`../Output_3_Trig_PeakAmp/level_<N>/`（每触发一份 per-event pkl + 汇总 `Trig_MAX_amp_df.csv`）
- **下游去向**：震级估计脚本 `2b_Est_Mag_with_GR_law_check.py` 会读 `Output_3_Trig_PeakAmp/level_<N>/Trig_MAX_amp_df.csv`，但**仅用于可选的振幅分支** `Quasi_Mag_Amp` 与「`max_RAWCCs` vs 峰值振幅」对照图；**最终震级 `Real_Mag` 用 `max_RAWCCs` 标定，不取 `amp_log_mean`/`amp_max_mean` 这两列**（详见上方「Run_3 在最终方案中的定位」与 `Run_4/.../说明文档.md` 的 2b 节）。

## 二、脚本说明

### 1. `1_Record_Amp_Parallel.py`（并行版，主线，实际产生 Output_3）

- **作用**：并行地把每个触发点回查 80Hz DAS 原始数据，提取各通道峰值振幅，逐事件存 pkl，并汇总成 `Trig_MAX_amp_df.csv`。
- **输入**：
  - 触发点：`../Output_2_Triggered_SCCs_points/level_{Threshold_level}/`（`Threshold_level=40`，可改）
  - 模板库：`../Output_0_Template_library/Template_library.csv`
  - MAD：`../Output_1_SCCs_and_MAD/MAD_arrays/20240424_102000_to_20240622_171000/12:00:00/MAD_Average_dict.pkl`
  - DAS 原始数据：`IN_DAS_data/continuous_scan_1h/`（`Read_DAS_data` 内写定的包内相对路径）
  - 关键参数（`Config` 类）：`fs=80`，`freq_band=[8,20]`，`das_dist_start=8300`/`das_dist_end=14000`，`dx≈16.335m`，`Search_win_left=1.5s`/`Search_win_right=2.5s`，时间范围 `2024-04-24 10:20:00 ~ 2024-06-22 17:10:00`，`num_cpus=min(10, cpu_count())`，`checkpoint_interval_events=100`
- **输出**：
  - 每事件 pkl：`../Output_3_Trig_PeakAmp/level_{N}/{Template}/amp_max_at_Rt_trig_<YYYY-MM-DD HH:MM:SS>.pkl`
  - 汇总表：`../Output_3_Trig_PeakAmp/level_{N}/Trig_MAX_amp_df.csv`（tab 分隔）
  - 断点续传：`.../Trig_MAX_amp_df_checkpoint.pkl`
  - 参数记录：`.../config.json`
- **核心处理逻辑**：
  1. 读 `Template_library.csv`，由 `infile_name` 唯一值自动生成模板名列表（覆盖 `Config` 硬编码的 5 个默认名）；据 `t_P_sec`/`t_S_sec` 建 `DF_Temp_Offset`。
  2. 载入 `MAD_Average_dict`；调 `Read_Collapse_group_df` 把所有模板触发点拼成 `events_df`，按 `Rt_trig` 排序。
  3. 断点续传：若存在 checkpoint，只处理仍为 NaN 的事件。
  4. 用 `multiprocessing.Pool(num_cpus).imap_unordered` 并行调 `process_event`：截窗 `[Rt_left-1.5s, Rt_right+2.5s]` 读 DAS 数据（带通 8–20Hz，取 8300–14000m 段）；`amp_max = max(|data|, axis=0)`；`amp_max_mean = mean(amp_max)`；`amp_log_mean = mean(log10(|amp_max|+1e-12))`；结果 dict 写入该模板子目录的 per-event pkl。
  5. 每 100 个事件写一次 checkpoint；结束后写最终 checkpoint 与 `Trig_MAX_amp_df.csv`。
- **依赖的 functions 模块**（release 根 `functions/` 下）：`readers.Read_DAS_data`、`readers.load_pkl`、`classify.Read_Collapse_group_df`。
- **备注**：`MAD_Avg_path` 与 `Read_DAS_data` 内的 DAS 默认路径均已设为基于 `PROJECT_ROOT` 的包内相对路径（`IN_DAS_data/continuous_scan_1h/`）；`Config.Temp_name_list` 在 `main()` 中被模板库实际内容覆盖；支持断点续传与 try/except 错误隔离。

### 2. `1_Record_Amp.py`（串行旧版，v4 遗留，不可使用）

- **作用**：与并行版功能等价，但为单进程 for 循环，面向 v4 目录结构。
- **主要差异**：带通 5–20Hz（并行版 8–20Hz）；硬编码 13 个模板名 `temp_0..temp_12`（v4 命名）；第 81 行引用从未定义的 `config` 对象，直接运行会 `NameError`；输出指向 `matched_filter_v4` 路径；与 v8 数据结构不兼容。
- **结论**：仅供历史溯源，不应运行。

## 三、脚本之间的执行顺序与依赖关系

两脚本是「二选一」版本，不存在串联关系。整体在流程中的位置：

```
Run_0 (模板库)                Run_1 (SCCs + MAD)
   │  Template_library.csv        │  MAD_Average_dict.pkl
   │                              │
   ▼                              ▼
Run_2 (触发) ──► Output_2_Triggered_SCCs_points/level_N/{Template}/*.pkl
                          │
                          ▼
        ┌─────────────────────────────────────────┐
        │  Run_3  1_Record_Amp_Parallel.py  （本步）│
        │  读触发点 + 回查 DAS 原始数据 → 峰值振幅   │
        └─────────────────────────────────────────┘
                          │
                          ▼
   Output_3_Trig_PeakAmp/level_N/
       ├── {Template}/amp_max_at_Rt_trig_*.pkl
       └── Trig_MAX_amp_df.csv
                          │
                          ▼
   震级估计脚本 2b_Est_Mag_with_GR_law_check.py
       读 Trig_MAX_amp_df.csv → amp_log_mean/amp_max_mean
       → Quasi_Mag → 与 NOA 震级线性回归 → Real_Mag → G-R 律 / b 值
```

运行本步前需先完成 Run_0、Run_1、Run_2（生成模板库、MAD、触发点）。

## 四、两脚本差异对照

| 维度 | `1_Record_Amp_Parallel.py`（采用） | `1_Record_Amp.py`（废弃） |
|---|---|---|
| 并行 | `multiprocessing.Pool`，10 进程 | 单进程 for 循环 |
| 带通 freq_band | 8–20 Hz | 5–20 Hz |
| 模板列表 | 由 `Template_library.csv` 自动生成（5 个 `template_*_80Hz`） | 硬编码 13 个 `temp_0..temp_12` |
| 输入/输出根目录 | release 根（相对路径，已 bootstrap） | 原指向 `matched_filter_v4`（已 bootstrap 但逻辑仍是旧版） |
| MAD 路径 | `12:00:00` 窗 | `4:00:00` 窗（v3_1） |
| level（阈值子目录） | `level_40`（参数化 `Threshold_level`） | 写死 `level_25` |
| 断点续传 / 错误处理 | 有 checkpoint、try/except、tqdm | 无 |
| 可否直接运行 | 是（生产脚本） | 否（`config` 未定义，`NameError`） |
| 配置落盘 | 写 `config.json` | 不写 |

## 五、数据说明

数据落在 `../Output_3_Trig_PeakAmp/`，详见该文件夹说明文档。

### 目录结构

```
Output_3_Trig_PeakAmp/
  level_15/  level_20/  level_25/  level_30/  level_35/  level_40/  level_50/
    config.json
    Trig_MAX_amp_df.csv
    Trig_MAX_amp_df_checkpoint.pkl
    template_0423_80Hz/   amp_max_at_Rt_trig_<YYYY-MM-DD HH:MM:SS>.pkl  ...
    template_0425_80Hz/   ...
    template_10_80Hz/     ...
    template_8_80Hz/      ...
    template_20_80Hz/     ...
```

### per-event pkl（`amp_max_at_Rt_trig_*.pkl`）

dict，15 个键，核心字段：

| key | 类型 | 含义 |
|---|---|---|
| `Rt_trig` / `Rt_left` / `Rt_right` | Timestamp | 去 S 偏移后的真实事件时刻及左右窗 |
| `t_trig` / `t_left` / `t_right` | Timestamp | CC 上触发位置及实际取数据时窗 |
| `Template` | str | 模板名 |
| `CCs_s_trig_ofMAD` | float | SCC / MAD |
| `amp_max` | ndarray float64, shape=(349,) | 各 DAS 通道峰值振幅（349 通道，8300–14000m，单位 DAS 应变率量级 ~1e-8） |
| `t_max` | DatetimeIndex, len=349 | 各通道峰值出现时刻 |
| `amp_max_mean` | float64 | `mean(amp_max)` |
| `amp_log_mean` | float64 | `mean(log10(abs(amp_max)+1e-12))`，**下游用作准震级** |

### `Trig_MAX_amp_df.csv`（汇总表）

tab 分隔，16 列：`CCs_s_trig, RAWCCs_s_trig, t_trig, width_trig, t_left, t_right, max_RAWCCs, t_arg_max, max_stalta, Rt_trig, Rt_left, Rt_right, CCs_s_trig_ofMAD, Template, amp_max_mean, amp_log_mean`。**下游震级估计脚本只用其中 `Rt_trig`、`Template`、`amp_log_mean`、`amp_max_mean` 四列**（按 `['Rt_trig','Template']` merge）。

### `config.json`

Run_3 运行参数与全部输入/输出路径的落盘记录，是「该 level 数据由何参数产生」的权威证据。
